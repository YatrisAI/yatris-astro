Contact-form synchronization and SMTP provisioning through the Yatris Product MCP (YatrisCMS#392, #390). `yatris forms plan` validates locally, then asks Yatris for a read-only comparison of each declaration with the recorded baseline (`.yatris/forms.lock.json`) and the current Yatris draft and publication (spec §4.1 drift matrix: `create`, `update_draft`, `noop`, `accept_remote`, `remote_drift`, `conflict`, `adopt_required`, `invalid`) and writes a gitignored plan file of paths and hashes. `yatris forms apply --plan <file>` refuses any declaration changed since the plan, saves Yatris drafts atomically with an idempotency key reused on retry, never publishes, and updates the lock. `yatris forms pull [--draft]` writes remote definitions only where no unsynchronized local edit would be lost, and can advance the baseline without a remote write. `yatris mail sync --env-file .env` imports customer SMTP settings as a pending profile without ever printing a value; empty variables send nothing. `yatris doctor` now checks declarations, `<YatrisForm>` mounts, redirect thanks routes, renderer capabilities and Yatris readiness, reporting remote checks as `unverified` (never passed) when offline (`--offline`), unpaired or without `YATRIS_MCP_TOKEN`. Exit codes: 0 ok, 1 invalid, 2 reconcile, 3 stale, 4 unpaired, 5 credentials, 69 not offered, 75 backend_unavailable. New sites gitignore `.yatris/forms.plan.json`.
